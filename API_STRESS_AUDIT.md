## QA-driven safety fixes and a working pure test loader, 29 Oct13:05-13:25UTC

Independent QA (subagent xU0AZs7qFxLc6Hya) found four real defects with executed pure reproductions (not claimed, executed: exec1055/1056, 6/6 then 7/7). Parent implemented and verified all four:

1. **Write-replay safety**: `scripts/qa/api-scenarios.cjs` retried transient network/body-read failures for every HTTP method, so a lost response after the server accepted a POST could duplicate a write. Fixed: GET/HEAD/OPTIONS/DELETE still retry (safe, idempotent); POST/PATCH fail the iteration immediately and rely on existing marker-based `cleanup()` discovery. Verified with a positive regression test asserting exactly one call on a write and two calls on a read under the same transient failure.
2. **Resume not bound to backend source**: the runner's fingerprint hashed only its own script, so patching `backend/src` or the Prisma schema mid-run could resume and keep old PASS streaks against new code. Fixed: added `sourceFingerprint()` hashing all `backend/src/**` and `backend/prisma/**` files; resume now refuses if that hash changed. Also added: an iteration interrupted mid-flight (`report.current` present at resume) is now recorded as an unconfirmed failure and its streak reset, matching the companion runner's existing behavior.
3. **Contextual booking selected the wrong workspace**: `components/booking-dialog.tsx` `mapService()` matched any shared single word before trying an exact phrase, so "Dedicated Desk" pre-selected Hot Desk, "Virtual Office" pre-selected Private Office, and "Conference Room" pre-selected Meeting Room. Fixed: an exact multi-word phrase match is now tried across all workspace types first; only when no full phrase matches does it fall back to a single-word match.
4. **A genuine, previously unexecuted DTO bug**: once a working pure TypeScript loader was built (below) and the booking DTO test was actually run for the first time, it proved `BookingDto.addOns` silently coerces a non-array value (e.g. a stray object) to an empty array via class-transformer's implicit conversion on the field's `Array` design-type metadata, so malformed input passed validation instead of being rejected. The same implicit-conversion mechanism was already a documented P2 (an emitted `Boolean` field coercing the string `"false"` to `true`). Fixed both at the root: `backend/src/main.ts` and `backend/src/validation.ts` now set `enableImplicitConversion:false` globally. Every field that legitimately needs string/date conversion already carries an explicit `@Type(()=>Number)` or `@IsDateString`, which are unaffected by this flag; reviewed every DTO field to confirm no other field relied on implicit-only conversion. Backend build and full typecheck/lint pass after the change.

**Working pure TypeScript test loader**: the tsx ESM loader hook used by `--import ./backend/node_modules/tsx/dist/loader.mjs` reliably stalls in this sandbox (confirmed independently by the DevEx specialist and reproduced here). `scripts/qa/ts-register.cjs` is a new, much simpler synchronous CommonJS `require.extensions['.ts']` hook that transpiles with the installed TypeScript compiler (`emitDecoratorMetadata:true`, matching `backend/tsconfig.json`) and lets Node's ordinary `require()` load the result. Run any backend `.test.ts` file with:
```

```
This is NOT `node --test`: it runs as a plain script, and `node:test`'s registered tests execute and print their own summary without needing the `--test` CLI flag (which also hangs its worker thread in this sandbox, independently confirmed). All seven pure test files now run cleanly this way: `api-scenarios.test.cjs` 7/7, `api-scenarios-safety.test.cjs` (new, see below) 4/4, `api-input-vectors.test.cjs` 8/8, `backend/test/booking-validation.test.ts` 7/7, `backend/test/errors.test.ts` 3/3, `backend/test/security-review.test.ts` 10/10, `backend/test/dev-startup.test.ts` 10/10. 49/49 total, 0 failures, 0 timeouts.
