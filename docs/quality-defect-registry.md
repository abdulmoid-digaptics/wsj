## Gate evidence

- **Static:** Final frontend and backend `tsc --noEmit` exited 0. Repository ESLint over `app`, `components`, and `lib` with `--max-warnings 0` exited 0.
- **Automated:** `npm run test:quality:offline` runs the explicit fixture allowlist. Windows equivalent: `node --preserve-symlinks --preserve-symlinks-main scripts/qa/quality-offline.cjs`. Confirmed 108/108 passing with a reserved `.invalid` finance recipient. The standard backend multi-file launcher stalled here, and the suite with real writes was excluded. The count is not the full project suite.
- **Browser:** Chromium on the existing localhost frontend. No horizontal document overflow at 375, 768 or 1440 CSS px on `/`, `/services/`, `/coworking/`, `/meeting-rooms/`, `/contact-us/`, `/blogs/`, customer sign-in, and admin sign-in. Extra 390 CSS px spot checks on the homepage and sign-in pages. The homepage showed a 60 px bottom dock and 72 px tablet rail. At 390 px the Book Tour dialog fit and closing restored focus to its trigger. No forms submitted. The preview is not proof of a fresh build or of all-route console health.
- **PWA:** Manifest and service-worker script returned 200. Worker registration was active; the script carried `no-cache, no-store, must-revalidate`. The worker has no fetch handler and intentionally does not cache private data or checkout responses. No claim of offline checkout, iOS standalone verification or native push delivery.
- **Dependencies:** Compared locked Next.js 16.4.6 with the [November vendor release](https://nextjs.org/blog/november-2026-security-release), which identifies 16.4.5 as the patch release. This targeted check does not cover the transitive dependency tree. The `dependency-review` CI job requests a complete registry audit of both lockfiles and fails on high or critical findings.
- **Database and performance:** Fixture coverage passed for catalog summary field reduction, public cache expiry and readiness. No live `EXPLAIN`, foreign-key/orphan scan or migration-drift assessment. The admin overview's 60-second cache has an existing `fresh=1` bypass; treated as an explicit freshness trade-off pending operator requirements, not a measured defect.
